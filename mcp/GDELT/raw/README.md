## The two summarize tools take a **window**, not an id

They're aggregate rollups, not record lookups. Input is `days` / `start_date` /
`end_date` plus filters, and `group_by` picks the bucket dimension. Nothing needs
to feed them an id, which is why they were captured twice.

**Their bucket shape changes with `group_by`.** This is the thing to settle
before writing a normalizer:

`summarize_events`, `group_by: date` → **5 fields**
```
key, event_count, article_count, latest_date, metrics{7}
```

`summarize_events`, `group_by: country` → **40 fields**
```
key (="United States"), group_by, latest_date, event_count,
conflict_event_count, cameoplus_event_count, fatality_event_count,
fatalities, fatality_event_rate, country_count, region_count,
article_count, avg/min/max_article_count,
avg/max/min_significance, avg/min/max_goldstein_scale,
avg/min/max_goldstein_severity, avg/min/max_magnitude,
avg/min/max_systemic_importance, avg/min/max_propagation_potential,
avg/min/max_market_sensitivity, avg/min/max_confidence, metrics{7}
```

`summarize_stories`, `group_by: date` → **23 fields**
```
key (="2026-09-27"), group_by, latest_date, story_count, article_count,
avg/min/max_article_count, stories_with_events, story_only_count,
linked_event_count, avg/min/max_linked_event_count,
stories_with_fatalities, fatalities, fatality_story_rate,
country_count, region_count, avg/max/min_significance, metrics{4}
```

`summarize_stories`, `group_by: category` → same 23 fields, different `key`
(`="cameoplus_political"`).

So a summarize normalizer keyed only on `key` + a count works for `date`, and
silently drops 35 fields for `country`. Which is exactly the decision to make.

**Empty buckets come back as `null`, not absent.** A `group_by: date` bucket for
a day with no coverage reads `event_count: 0, article_count: 0, latest_date:
null, metrics: {...}` — every optional field is null rather than missing. A
normalizer using `?? 0` will turn "no data" into "zero".

**`group_by: date` also returns sparse days.** A 7-day window gave 6 buckets,
one of them an empty day. Don't assume `data.length === days`.

**`summarize_stories` carries two extra envelope keys** the events version
doesn't: `notice` and `counting_basis`. Read them — the notice explains that
empty means no coverage, not zero activity.

## The three by-id tools take an id, chained from a search

`get_event` ← `search_events[0].id`, `get_story` and `get_story_articles` ←
`search_stories[0].id`. Confirmed live: search returned `8608afb1d928` and
`get_story` returned `id: 8608afb1d928`.

**Ids are short hex, not URLs.** Stories `8608afb1d928`; events are
family-prefixed (`conflict_574b2dc178a74941`). The record's `url` is the human
page — passing that to `get_story` will not work.

**`data` shape differs.** `get_event` and `get_story` return a single object;
`get_story_articles` returns an array. Check before indexing.

Worth knowing while deciding: `get_story_articles` keeps only `id` and `title`,
dropping `url`, `domain`, `article_date`, `language`, `role` and `rank` — so a
normalized article cannot be cited. `get_story` drops `significance`, which
`search_stories` keeps.
